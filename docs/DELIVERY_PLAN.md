# AICore 交付路线图与文档产出计划

## 1. 目标与范围

本计划用于将 `PRD_V3.0` 转化为可执行研发任务，确保“需求 -> 设计 -> 开发 -> 测试 -> 发布”每一阶段有明确产出和负责人。

## 2. 分阶段执行计划

| 阶段 | 周期 | 关键目标 | 必交付文档 | 责任角色 |
| :--- | :--- | :--- | :--- | :--- |
| P1 底座与云端 | 3周 | 跑通在线 SSE 流式会话 | 《接口对接清单》《SSE 异常码策略》 | 架构师/后端/客户端 |
| P2 离线引擎攻坚 | 4周 | ONNX + LiteRT 双引擎可运行 | 《离线推理适配报告》《模型兼容矩阵》 | 算法/客户端 |
| P3 交互串联 | 3周 | SessionManager 冷启动与降级闭环 | 《状态机说明书》《降级测试报告》 | 客户端/测试 |
| P4 多模态与适配 | 2周 | 语音/文件输入 + 折叠屏/桌面布局 | 《多模态能力白名单》《平台适配清单》 | 客户端/测试 |
| P5 打磨发布 | 2周 | 性能达标与全平台发包 | 《性能验收报告》《发布回归报告》 | 测试/运维/产品 |

## 3. 关键里程碑（建议日期）

> 以 2026-04-20 为研发启动日的建议排期：

- M1（2026-05-11）：P1 通过，完成在线端到端流式会话。
- M2（2026-06-08）：P2 通过，桌面端离线模型稳定输出。
- M3（2026-06-29）：P3 通过，配置恢复与降级策略上线。
- M4（2026-07-13）：P4 通过，多模态与宽屏适配完成。
- M5（2026-07-27）：P5 通过，形成候选发布版本（RC）。

## 4. 文档治理与归档机制

- 统一目录：`docs/`。
- 命名规范：`[模块]_[主题]_[版本].md`。
- 更新要求：
  - 需求变更：更新 PRD 并记录变更条目。
  - 架构变更：新增 ADR（见 `ARCHITECTURE_DECISIONS.md`）。
  - 发布前：补齐验收与回归文档。
- 评审节奏：每周固定一次文档审查会，阻塞项需形成行动人和截止时间。

## 5. 风险台账（首版）

| 风险 | 影响 | 应对策略 |
| :--- | :--- | :--- |
| 移动端离线模型内存超限 | 影响可用性与稳定性 | 提前进行 2B 模型内存剖析并设置能力降级 |
| 多供应商 API 行为差异 | 影响模型切换体验 | 在 network 层统一错误码与超时策略 |
| 跨平台文件选择能力差异 | 影响多模态一致性 | input-core 建立平台能力检测与灰度拦截 |
| Web 无离线能力导致认知偏差 | 影响用户预期 | UI 显式提示“Web 仅支持在线模式” |

## 6. 产品负责人执行准则

1. 每周同步：里程碑、风险、依赖、决策。
2. 每个阶段结束必须有“可演示成果 + 可审计文档”。
3. 所有关键逻辑先归档后开发，避免口头共识失真。
